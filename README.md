# PEPG — Platform-Enabled People Governance

> An open-source governance model and problem infrastructure for distributed public problem-solving.

[![PEPG 2.0](https://img.shields.io/badge/PEPG-2.0-blue)](https://doi.org/10.5281/zenodo.22133939)
[![Open Source](https://img.shields.io/badge/Open%20Source-GitHub-green)](https://github.com/miladhp94/pepg)

## What is PEPG?

**Platform-Enabled People Governance (PEPG)** is a governance model designed to connect people, institutions, expertise, resources, implementation, and oversight around public problems.

PEPG does not require all participation to happen on one social network or technology platform.

People may identify a problem in one place, discuss solutions somewhere else, implement a project through another organization, and publish monitoring reports on another platform.

PEPG provides the governance layer that connects these activities through a persistent **Problem ID**.

---

## PEPG 2.0

PEPG 2.0 introduces the **PEPG Board**.

The PEPG Board is an open-source and potentially global infrastructure for registering, verifying, discussing, revising, and connecting public problems.

Each problem receives a persistent identifier such as:

`PEPG-0001`

or

`PEPG-0002`

The Problem ID can then be referenced across different platforms and organizations.

---

## The PEPG Board

The Board provides common governance services such as:

- Problem registration
- Problem verification
- Account integrity
- Problem-definition revision
- Community voting
- Trusted-authority verification
- Problem relationships
- Provenance and history
- External links
- Auditability

The Board is not intended to replace every social network or communication platform.

It provides a common infrastructure for connecting them.

---

## Problem Definition

A problem is not necessarily permanently defined by its first proposer.

Other participants may propose:

- An improved definition
- A sub-problem
- A separate problem
- Evidence that the problem is incorrectly defined
- Evidence that the problem is insufficiently supported

The original definition is preserved as part of the problem history.

A new definition can become accepted through transparent governance procedures involving the proposer, community participation, and where appropriate, trusted authorities.

## Example

### PEPG-0002

**Problem:**

Poor asphalt quality on an Abstract Street in Tanzania.

The problem may contain:

- Problem definition
- Verification status
- Definition revisions
- Community votes
- Evidence
- Related problems
- External solution groups
- Implementation references
- Oversight references
- Reports

The actual solution does not have to be developed inside the PEPG Board.

It may be developed by citizens, engineers, organizations, companies, or government institutions on other platforms.

---

## Government and PEPG

PEPG does not seek to eliminate government institutions.

Government organizations can participate as:

- Trusted verification authorities
- Regulators
- Funders
- Project owners
- Implementers
- Oversight institutions

At the same time, PEPG separates functions where possible to reduce unnecessary concentration of power.

No single actor should automatically control:

**Problem → Verification → Funding → Implementation → Oversight**

## Open Source

The PEPG Board is being developed openly on GitHub.

The goal is to allow researchers, developers, citizens, institutions, and other communities to examine, challenge, improve, and extend the model.

## Vision

PEPG aims to explore a governance architecture in which public problems become transparent, persistent, revisable, and connected to distributed human capacity.

The objective is not to create another social network.

The objective is to create an open infrastructure through which people and institutions can coordinate around public problems.
